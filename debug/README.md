# Debug Infrastructure

This directory contains the debug workflow infrastructure for systematic bug fixing in the Mindmap Learning App.

---

## Overview

Every bug fix MUST follow the **Repro → Trace → Fix → Verify** workflow.

This infrastructure provides:
- 📋 **Documentation**: Workflow, decision trees, templates
- 🔍 **Tracing utilities**: Request ID propagation, debug logging
- ✅ **Verification scripts**: Doctor and triage automation
- 🤖 **AI enforcement**: Augment rules to ensure compliance

---

## Quick Start

### Enable Debug Tracing

```bash
# Frontend + Backend
NEXT_PUBLIC_DEBUG_TRACE=1 npm run dev:web
DEBUG_TRACE=1 npm run dev:cms
```

### Run Verification

```bash
# Quick health check
npm run doctor

# Full check with artifacts
npm run triage
```

### Debug a Bug

1. **Read**: `HOW_TO_USE.md` (start here!)
2. **Follow**: `WORKFLOW.md` (the mandatory process)
3. **Classify**: `plans/code-never-reached.md` (decision tree)
4. **Document**: `templates/AI_DEBUG_BUNDLE.md` (fill this for PRs)

## Documentation

### Core Workflow

**`WORKFLOW.md`** - The mandatory 7-step process:
1. REPRODUCE
2. CLASSIFY BOUNDARY
3. GATHER EVIDENCE
4. INSTRUMENT
5. FIX
6. VERIFY
7. DOCUMENT

### Decision Tree

**`plans/code-never-reached.md`** - Systematic approach to "code never reached" bugs:
- Frontend event never fires
- Next.js route renders but fetch never happens
- Request hits browser network but not backend
- Request hits backend entry but not Payload handler/hook
- Handler runs but branch not reached
- Async never fired

### Templates

**`templates/AI_DEBUG_BUNDLE.md`** - Required for all bug fix PRs:
- Environment info
- Repro steps
- Boundary classification
- Evidence pack (requestId, logs, network traces)
- Root cause
- Fix description
- Verification

## Tracing Utilities

### Frontend (Next.js)

**Location**: `apps/mindmap-web/lib/`

- **`requestId.ts`**: Generate and propagate request IDs
- **`fetcher.ts`**: Traced fetch wrapper with logging
- **`middleware.ts`**: Automatic request ID propagation

**Usage**:
```typescript
import { tracedFetch, debugLog } from '@/lib/fetcher'

const response = await tracedFetch('/api/mindmaps', {
  method: 'POST',
  requestId: 'req_abc123', // optional
})

debugLog('Action', { requestId, data })
```

### Backend (Payload CMS)

**Location**: `apps/mindmap-cms/src/lib/`

- **`debugTrace.ts`**: Debug logging utilities
- **`entryLogger.ts`**: Automatic request logging plugin

**Usage**:
```typescript
import { debugTrace, getRequestId } from '@/lib/debugTrace'

const requestId = getRequestId(req)
debugTrace('hookName', { requestId, data })
```

## Verification Scripts

### Doctor Script

**Location**: `scripts/doctor.js`

Runs health checks for both frontend and backend:
- Lint
- Typecheck
- Tests
- Build (optional with `--fast`)

**Usage**:
```bash
npm run doctor              # Full check
npm run doctor -- --fast    # Skip builds
npm run doctor -- --frontend  # Frontend only
npm run doctor -- --backend   # Backend only
```

### Triage Script

**Location**: `scripts/triage.js`

Runs doctor and captures artifacts to `debug/`:
- `latest-output.txt` - Full output
- `latest-summary.json` - Pass/fail matrix
- `latest-failures.json` - Failure details

**Usage**:
```bash
npm run triage
npm run triage -- --fast
```

## Debug Flags

### Environment Variables

**Frontend** (`NEXT_PUBLIC_DEBUG_TRACE`):
- Enables request ID generation
- Enables fetch wrapper logging
- Enables middleware logging

**Backend** (`DEBUG_TRACE`):
- Enables entry logger
- Enables debugTrace() calls
- Enables hook tracing

### Setting Flags

**Option 1: Inline**
```bash
NEXT_PUBLIC_DEBUG_TRACE=1 npm run dev:web
DEBUG_TRACE=1 npm run dev:cms
```

**Option 2: .env.local files**

`apps/mindmap-web/.env.local`:
```
NEXT_PUBLIC_DEBUG_TRACE=1
```

`apps/mindmap-cms/.env.local`:
```
DEBUG_TRACE=1
```

## PR Requirements

Every bug fix PR MUST include:

1. ✅ Filled `AI_DEBUG_BUNDLE.md` (copy into PR description)
2. ✅ Boundary classification with evidence
3. ✅ RequestId captured in both frontend and backend logs
4. ✅ Root cause explanation
5. ✅ Fix description
6. ✅ `npm run doctor` output pasted
7. ✅ Tests added/updated OR explanation
8. ✅ No secrets logged
9. ✅ Diff is minimal (≤ 5 files, ≤ 200 LOC unless justified)

See `.github/pull_request_template.md` for the full checklist.
