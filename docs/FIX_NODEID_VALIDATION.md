# Fix: nodeId Field Validation Error

## Problem

When creating mindmap nodes via the API, the request was failing with:

```
[INFO] The following field is invalid: nodeId
POST /api/mindmap-nodes 400 in 21ms
```

## Root Cause

The issue was a **validation order problem** in Payload CMS:

1. **Field Validation Runs First**: Payload validates all `required` fields before running hooks
2. **Hook Runs Second**: The `ensureStableNodeId` hook auto-generates the `nodeId` 
3. **Conflict**: The field was marked as `required: true`, so validation failed before the hook could generate the ID

### Validation Flow (Before Fix)

```
Request → Field Validation → ❌ FAIL (nodeId required but missing)
                           ↓
                    Hook never runs
```

### Expected Flow (After Fix)

```
Request → Field Validation → ✅ PASS (nodeId optional)
                           ↓
                    beforeChange Hook → Auto-generate nodeId
                           ↓
                    Save to database
```

## Solution

Changed the `nodeId` field from `required: true` to `required: false` in the schema, since the hook ensures it's always present.

### Code Change

**File**: `apps/mindmap-cms/src/collections/MindmapNodes.ts`

**Before**:
```typescript
{
  name: 'nodeId',
  type: 'text',
  required: true, // ❌ Validation fails before hook runs
  unique: true,
  label: 'Node ID',
  admin: {
    readOnly: true,
    description: '⚠️ STABLE ID - Never changes after creation. Auto-generated.',
  },
}
```

**After**:
```typescript
{
  name: 'nodeId',
  type: 'text',
  required: false, // ✅ Validation passes, hook generates ID
  unique: true,
  label: 'Node ID',
  admin: {
    readOnly: true,
    description: '⚠️ STABLE ID - Never changes after creation. Auto-generated by hook.',
  },
}
```

## How It Works

### The Hook (`ensureStableNodeId`)

Located in `apps/mindmap-cms/src/hooks/ensureStableNodeId.ts`:

```typescript
export const ensureStableNodeId: CollectionBeforeChangeHook = async ({
  data,
  operation,
  originalDoc,
}) => {
  // On CREATE: Auto-generate nodeId if not provided
  if (operation === 'create') {
    if (!data.nodeId) {
      data.nodeId = uuidv4() // Generate UUID
    }
    return data
  }

  // On UPDATE: Prevent nodeId modification
  if (operation === 'update') {
    if (originalDoc && data.nodeId && data.nodeId !== originalDoc.nodeId) {
      throw new Error('nodeId cannot be changed after creation')
    }
    data.nodeId = originalDoc.nodeId // Preserve original
  }

  return data
}
```

**Creating a node WITHOUT nodeId** (recommended):

## Key Learnings

1. **Payload CMS Hook Order**: Field validation runs **before** hooks
2. **Auto-Generated Fields**: Should be `required: false` in schema if generated by hooks
3. **Validation vs Business Logic**: Use hooks for business logic, not field validation
4. **nodeId Stability**: The hook ensures nodeId is always present and immutable, even though the field is not required in the schema
